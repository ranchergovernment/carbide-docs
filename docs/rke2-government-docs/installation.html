Installation

info

RKE2 Government currently supports installation only through the air-gapped method. Use this method even when your nodes are in a connected environment.

These steps install an RKE2 Government server or agent node. They assume you have already provisioned the node and are using the bundled containerd as the container runtime.

  • Server nodes run the Kubernetes control plane, etcd, and workloads. Every cluster needs at least one server node.
  • Agent nodes run workloads only and join an existing server.

Steps 1 and 2 are the same for both node types. Step 3 differs depending on whether you are installing a server or an agent. Install the first server node before installing any agent nodes.

Replace <VERSION> in the commands below with the RKE2 Government version you want to install. Available versions are listed on the Carbide Portal.

Step 1: Get the RKE2 Government Artifacts​

Download the RKE2 Government artifacts on a connected machine using one of the following options.

Option A: Download from the Carbide Portal​

Log in to the Carbide Portal, select RKE2 Government, and download the pre-built Hauler tarball for your version. Then skip to Step 2.

Option B: Sync with Hauler​

This option uses Hauler. Follow the Hauler installation instructions if you do not already have it installed.

  1. Download the Carbide public key, which Hauler uses to verify the artifact signatures.

    curl -sfOL https://raw.githubusercontent.com/ranchergovernment/carbide/main/carbide-key.pub

  2. Log in to the Carbide Secured Registry with your Carbide credentials, sync the RKE2 Government product to your Hauler store, and save the store to a tarball.

  • Harbor Registry (Standard)
  • Azure Container Registry (Legacy)
hauler login registry.ranchercarbide.dev -u <USERNAME> -p <PASSWORD>
hauler store sync --products rke2-government=<VERSION> --product-registry registry.ranchercarbide.dev --key carbide-key.pub --platform linux/amd64
hauler store save --filename rke2-government.tar.zst
hauler login rgcrprod.azurecr.us -u <USERNAME> -p <PASSWORD>
hauler store sync --products rke2-government=<VERSION> --product-registry rgcrprod.azurecr.us --key carbide-key.pub --platform linux/amd64
hauler store save --filename rke2-government.tar.zst
  1. Copy rke2-government.tar.zst and the Hauler binary to the RKE2 Government node.

Step 2: Load the Artifacts​

  1. On the node, load the tarball into a local Hauler store.

    hauler store load --filename rke2-government.tar.zst

  2. List the RKE2 Government artifacts in the store. These include the binary tarball, checksum file, and install script, and are the artifacts whose references contain /carbide/. This command requires jq.

    hauler store info --output json | jq -r '[.artifacts[].reference | select(contains("/carbide/"))] | unique[]'

  3. Extract each of those artifacts into a working directory.

    mkdir -p /root/rke2-artifacts && cd /root/rke2-artifacts
    for ref in $(hauler store info --output json | jq -r '[.artifacts[].reference | select(contains("/carbide/"))] | unique[]'); do
      hauler store extract "$ref"
    done

    You can also run hauler store extract <REFERENCE> individually for each reference listed in the previous step.

Disconnected Environments​

If you are running in an air-gapped environment, make the RKE2 Government images available to the node using one of the following options.

Option A: Copy the Images to the Local Images Directory​

Save the images from the Hauler store directly into the RKE2 images directory. RKE2 imports any image tarballs in this directory into containerd on startup. Repeat this on every node in the cluster.

mkdir -p /var/lib/rancher/rke2/agent/images/
hauler store save --containerd --filename /var/lib/rancher/rke2/agent/images/rke2-government.tar.zst

Option B: Copy the Images to an Existing Registry​

If you already have a private registry in your environment, use Hauler to copy the store contents to it. If the registry requires authentication, log in first.

hauler login <REGISTRY_URL> -u <username> -p <password>
hauler store copy registry://<REGISTRY_URL>

Then configure RKE2 Government to pull its images from that registry by adding the following to /etc/rancher/rke2/config.yaml on each node:

system-default-registry: <REGISTRY_URL>

If the registry requires authentication or uses a private certificate authority, also configure /etc/rancher/rke2/registries.yaml. See the upstream private registry documentation for details.

Step 3: Install RKE2 Government​

  • Server Node
  • Agent Node

  1. Run the install script, setting INSTALL_RKE2_ARTIFACT_PATH to the directory that contains the extracted artifacts.

    INSTALL_RKE2_ARTIFACT_PATH=/root/rke2-artifacts sh install.sh

  2. (Optional) Create /etc/rancher/rke2/config.yaml with any configuration for the node. See Configuration.

  3. Enable and start the rke2-server service.

    systemctl enable rke2-server
    systemctl start rke2-server

  4. Follow the service logs to monitor startup.

    journalctl -u rke2-server -f

  5. Once the server is running, retrieve the node token. You need this token to join additional server and agent nodes to the cluster.

    cat /var/lib/rancher/rke2/server/node-token

To add more server nodes to the cluster, create /etc/rancher/rke2/config.yaml on each new server before starting the service, pointing it at the first server:

server: https://<FIRST_SERVER_IP>:9345
token: <NODE_TOKEN>

  1. Run the install script with INSTALL_RKE2_TYPE set to agent, and INSTALL_RKE2_ARTIFACT_PATH set to the directory that contains the extracted artifacts.

    INSTALL_RKE2_TYPE="agent" INSTALL_RKE2_ARTIFACT_PATH=/root/rke2-artifacts sh install.sh

  2. Create /etc/rancher/rke2/config.yaml with the address of a server node and the node token retrieved from that server.

    mkdir -p /etc/rancher/rke2
    cat <<EOF > /etc/rancher/rke2/config.yaml
    server: https://<SERVER_IP>:9345
    token: <NODE_TOKEN>
    EOF

  3. Enable and start the rke2-agent service.

    systemctl enable rke2-agent
    systemctl start rke2-agent

  4. Follow the service logs to monitor startup.

    journalctl -u rke2-agent -f

Step 4: Validate STIG Compliance​

After the cluster is running, use the Rancher Compliance Operator to scan the cluster against the RKE2 STIG profile and confirm that it is in a compliant state. See RKE2 STIG Scanning for instructions on installing the operator and running a scan.

If you have overridden any STIG defaults in your configuration, review the scan results for any findings those changes introduce.

See the upstream RKE2 documentation for more information on air-gapped installation and configuration.
